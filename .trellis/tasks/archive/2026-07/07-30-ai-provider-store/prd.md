# 多提供商基础设施与设置页二级面板

> 父任务：`.trellis/tasks/07-30-ai-multi-provider` —— 三协议实测规格、CORS 证据、跨阶段验收标准见父任务 `prd.md`。

## Goal

把 `AiSettings` 从单套 `{baseUrl, apiKey, model}` 改为多提供商列表，设置页改成「列表 → 详情」二级面板，并让每本书记住自己用哪个提供商。本阶段只支持现有的 OpenAI 兼容协议，但预留 `protocol` 字段供阶段 2 分发。

## Requirements

### R1 多提供商数据模型

`AiProvider` 至少包含：稳定 `id`、用户自定义 `name`、`protocol`（本阶段仅 `"openai"`，枚举预留 `"gemini"` / `"anthropic"`）、`baseUrl`、`apiKey`、该提供商独立的模型列表缓存与拉取时间。

`AiSettings` 改为 `{ providers: AiProvider[], defaultProviderId?, defaultModel? }`。

### R2 老数据零成本迁移

读取旧 `yudu_ai_settings`（`{baseUrl, apiKey, model}`）时自动转成一个名为「默认」的 openai 提供商，并把旧的 `yudu_ai_models_cache` 并入该提供商的模型缓存。用户不需要重填任何东西，迁移对用户不可见。

### R3 设置页二级面板

- **一级**：提供商列表，每行显示名称、协议、模型数、是否为默认；操作为编辑 / 删除 / 设为默认。
- **二级**：单个提供商的详情表单——名称、协议选择、Base URL、API Key、获取模型列表、已缓存模型数。
- 「＋ 添加提供商」进入空白详情面板。
- 删除提供商需二次确认；删除的若是默认提供商，默认指向清空。
- 详情面板的返回操作要能回到列表。

### R4 书级绑定提供商

- `books` 表新增列记录该书的提供商 id（现有 `studio_model` 列继续存模型名）。
- `StudioBookDetail` 暴露该字段，`PATCH /api/studio/books/:id` 支持更新。
- 老作品该字段为空，生成时回退到全局默认提供商——行为等同改造前。

### R5 模型选择器跨提供商

创作台的模型选择器列出所有提供商的所有模型，显示为「提供商名 / 模型 id」，选中后同时记录提供商与模型。搜索需同时匹配提供商名与模型 id。

### R6 生成链路改用提供商

`requireAi()` 的就绪判断、`runStream` 取 baseUrl/apiKey/model 的逻辑，全部改为「先解析本书的提供商，回退全局默认」。未配置任何提供商时给出可读提示。

## Constraints

- 密钥仍只存浏览器 localStorage，不上传服务器。
- 不改动创作台五个步骤的业务逻辑与提示词。
- 不引入新 runtime 依赖。
- 本阶段**不实现** Gemini / Anthropic 的请求构造与流式解析（阶段 2）；`protocol` 字段可存但只有 `"openai"` 会被实际使用。
- D1 迁移必须同时应用到本地与生产。
- `MAX_STUDIO_MODEL_CHARS = 200` 的既有校验保留。

## Acceptance Criteria

- [ ] 设置页显示提供商列表，可添加多个提供商
- [ ] 点提供商进入详情面板编辑，可返回列表
- [ ] 每个提供商能独立「获取模型列表」，模型数各自显示且互不覆盖
- [ ] 可删除提供商（带二次确认）、可设为默认
- [ ] **改造前配置好的用户打开设置页，看到一个名为「默认」的提供商，地址/密钥/模型列表都在**，不需要重填
- [ ] 创作台模型选择器显示「提供商名 / 模型 id」，搜索能匹配提供商名
- [ ] 在 A 提供商的模型下生成 → 切到另一本书用 B 提供商 → 回到第一本书，仍是 A
- [ ] 老作品（无提供商记录）能正常生成，走全局默认
- [ ] 未配置任何提供商时点生成，给出可读提示而非崩溃
- [ ] `aiSettings` 迁移逻辑单测覆盖：旧格式、旧格式+模型缓存、新格式、空、损坏 JSON
- [ ] 后端单测覆盖新列的读写与非法值降级
- [ ] `pnpm -r typecheck` 与 `pnpm -r test` 全绿

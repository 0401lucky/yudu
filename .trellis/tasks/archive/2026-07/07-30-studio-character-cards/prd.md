# 人设改为结构化角色卡

## Goal

让 AI 生成的人设从「一句话概括」变成「有血有肉的角色卡」：把 `StudioCharacter` 从 3 字段扩为 8 个维度，AI 按块输出而非按行，UI 用可折叠卡片编辑。

## Background / 根因

用户反馈「人设不够丰满」。查证后是三个原因叠加，缺一不可解：

1. **提示词直接要求「一段话」**（`studioPrompts.ts:144-145`）：格式写死为 `姓名｜身份/角色｜性格与外貌与关系（一段话）`，既无维度清单也无字数要求。
2. **解析器按行切分是硬天花板**（`parseCharactersFromAi:151-177`）：一个角色一行，AI 不可能在一行里写 500 字。这比提示词更根本。
3. **数据结构只有 3 个字段**：`name` / `role` / `description`，UI 里 description 是 `rows={2}` 的小框，从存储到视觉都在暗示「短」。

因此只改提示词收益有限，必须连解析与数据结构一起动。

## Requirements

### R1 八维角色卡字段

`StudioCharacter` 新增 8 个可选字段：

| 字段 | 界面标签 | 含义 |
|---|---|---|
| `ageIdentity` | 年龄与身份 | 岁数、社会身份、职业出身 |
| `appearance` | 外貌与第一印象 | 长相、气质、穿着、给人的第一感觉 |
| `personality` | 性格 | 性格底色与矛盾面 |
| `background` | 背景经历 | 出场前的关键经历 |
| `motivation` | 动机与目标 | 想要什么、为什么、愿意付出什么 |
| `flaw` | 缺陷与软肋 | 弱点、怕什么、会在哪里失控 |
| `speech` | 说话方式 | 语气、口头禅、话多话少 |
| `relations` | 与其他角色的关系 | 关系网与张力 |

原 `role` 字段语义收敛为「故事定位」（主角 / 反派 / 导师…），界面标签与 placeholder 同步明确，避免与「年龄与身份」混淆。

### R2 AI 按块生成

- 生成人设时 AI 按「一个角色一块」输出，块内每个维度一行，块间空行分隔。
- 提示词给出全部 8 个维度的字段名与写作要求（要具体、可感、避免空泛标签）。
- 生成 3～6 个角色，且要求角色之间在性格与目标上有差异与张力。

### R3 解析与容错

- 主解析：按块切分，块内按「字段名：值」扫描。
- 退化解析：若按块解析出 0 个角色，退回旧的「按行 ｜ 切分」逻辑，把内容放进 `description`。保证模型不听话时不会全盘失败。
- 解析出 0 个角色时报可读错误，不清空用户已有人设。

### R4 折叠卡片 UI

- 每个角色一张可折叠卡片，收起时显示「姓名 · 故事定位」，展开后显示全部字段。
- 默认全部收起（角色多时不至于一屏塞满）；手动新增的角色默认展开。
- 每个字段一行标签 + 多行输入框，字段旁不需要逐个说明文字（标签已自解释）。

### R5 旧数据兼容

- 保留 `description` 字段。旧作品的单段描述原样保留，在卡片展开区以「旧描述」标注展示且可编辑，不丢失。
- 新字段对旧数据为空，用户可重新生成或手填。
- **不做**「AI 把旧描述拆成各字段」的功能。

### R6 下游打通

`formatCharacters` 输出全部维度，使总大纲、分章细纲、正文生成都能拿到完整角色信息。

## Constraints

- 老作品数据必须可正常打开、编辑、保存。
- 不改动立项 / 总大纲 / 分章细纲 / 正文四个步骤的 UI。
- 不改动破限（18+）逻辑与提示词内容。
- `studio_assets` 走 `normalizeAssets` 字段白名单，新字段必须同步补上，否则被静默丢弃（见 `.trellis/spec/api/backend/database-guidelines.md`）。
- 无 D1 迁移：新字段在 `studio_assets` 的 JSON 内。
- 遵循仓库既有风格：中文注释、Tailwind + CSS 变量 token、纯文本解析约定。

## Acceptance Criteria

- [ ] 点「AI 生成人设」后，每个角色 8 个维度都被填上，内容明显比改造前详细
- [ ] 角色卡默认收起，显示「姓名 · 故事定位」，点击可展开看到全部字段
- [ ] 「添加角色」新增的空卡片默认展开
- [ ] 任一字段手改后点「保存人设」，刷新页面能正确回显
- [ ] 打开改造前创建的老作品，原单段描述在「旧描述」区可见且可编辑保存
- [ ] AI 若回旧格式（`姓名｜身份｜描述`），退化解析仍能生成角色而不是报错
- [ ] AI 回完全不符格式的内容时，报错且不清空已有人设
- [ ] 生成正文时提示词里包含角色的动机、软肋、说话方式等维度
- [ ] `parseCharactersFromAi` 单测覆盖：新块格式、旧行格式退化、字段缺失、角色数、乱答
- [ ] `normalizeAssets` 单测覆盖新字段保留
- [ ] `pnpm -r typecheck` 与 `pnpm -r test` 全绿

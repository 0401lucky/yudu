# 优化创作台立项流程

## Goal

把 AI 小说创作台的「立项」步骤从「5 个无引导的空白输入框」改造成「说一句想看的故事 → AI 生成整套立项方案 → 用户点选微调」的流程，让用户不必先想清楚专业术语就能开工。

## Background / 现状问题

当前立项面板（`apps/web/src/pages/StudioWorkPage.tsx:558-628`）存在四个具体问题：

1. **零引导**：书名、类型、基调、目标篇幅、备注全是空白 `input`/`textarea`，没有占位示例、没有候选项、没有字段说明。用户看不懂每个字段该填什么。
2. **无 AI 起名**：新建作品固定写死 `title: "未命名作品"`（`StudioListPage.tsx:52`），全流程没有任何生成书名的入口。
3. **术语不可猜**：「类型」「基调」是自由文本，用户无法知道系统期望「玄幻」还是「穿书」还是「第一人称」。
4. **没有地方描述想法**：用户脑中真正有的是「我想看一个 XX 的故事」，但面板里唯一能装它的是叫「备注」的框——名称与位置都没有任何暗示。

附带发现的两个既有缺陷（在本任务范围内一并修复，因为都属于立项数据）：

- `autoChapterCount` 只存在于组件 local state（`StudioWorkPage.tsx:64`），从未持久化，刷新页面即丢失。
- `formatPremise`（`studioPrompts.ts:116`）只把 4 个字段喂给下游，用户在立项写的内容对人设/大纲/正文的影响面偏窄。

## Requirements

### R1 灵感输入区

- 立项面板顶部新增「你想看一个什么样的故事？」多行输入框，作为 AI 立项的主输入。
- 输入框 placeholder 为一段真实可读的示例文案，而非「请输入…」。
- 输入框下方提供 4~6 个灵感示例标签（如「都市异能」「宫斗」「星际种田」「重生复仇」），点击后把对应示例句填入输入框。
- 提供主按钮「AI 帮我立项」，流式生成。

### R2 AI 一次生成整套立项

「AI 帮我立项」根据灵感输入一次性产出并回填：

- 3 个书名候选（第一个自动填入书名字段，其余作为可点选候选展示）
- 类型（可多个）
- 基调（可多个）
- 目标篇幅（单个）
- 一句话卖点

生成后所有字段仍可手动编辑。解析失败时给出可读错误，不得清空用户已有内容。

### R3 书名单独重生成

书名字段旁提供「⟳ 换一批书名」，只重新生成 3 个书名候选，不影响其他字段。

### R4 字段可点选化 + 说明文字

- 类型：预置标签，**多选**，末尾提供「＋自定义」补充任意词。
- 基调：预置标签，**多选**，同样支持自定义。
- 目标篇幅：预置标签，**单选**。
- 上述三个字段各配一行灰色说明文字，回答「这个字段是什么意思」。

### R5 字段语义调整

- 新增「一句话卖点」字段。
- 原「备注」字段 UI 文案改为「额外要求」，placeholder 举例说明它用来放硬性约束（如「主角必须叫林晚」「别写重生梗」）。底层字段名 `notes` 不变。

### R6 数据持久化与下游打通

- 新增字段随立项一并保存，后端不得丢弃。
- `autoChapterCount` 持久化到立项数据。
- 新增的「故事想法」「一句话卖点」进入后续人设/大纲/细纲/正文的提示词。

## Constraints

- 老作品数据必须兼容：所有新字段可选，缺失时行为与现在一致。
- 未配置 API 时，立项面板所有字段仍可手填保存；点击 AI 按钮走现有 `requireAi()` 提示路径。
- 不改动人设 / 总大纲 / 分章细纲 / 正文四个步骤的 UI。
- 不改动破限（18+）相关逻辑与提示词。
- 不做「新建作品时弹出引导向导」——本次只改立项面板本身。
- 遵循仓库既有风格：中文注释、Tailwind + CSS 变量主题、纯文本｜分隔的 AI 输出约定。

## Acceptance Criteria

- [ ] 立项面板顶部有故事想法输入框，带真实示例 placeholder 与可点击的灵感示例标签
- [ ] 点「AI 帮我立项」后，书名、类型、基调、篇幅、卖点五项被自动填充，且书名给出 3 个可点选候选
- [ ] 「⟳ 换一批书名」只刷新书名候选，其他字段不变
- [ ] 类型与基调可多选预置标签并支持自定义词；篇幅为单选标签
- [ ] 类型 / 基调 / 篇幅 三个字段均有一行说明文字
- [ ] 「备注」显示为「额外要求」且 placeholder 给出约束类示例
- [ ] 保存立项后刷新页面，故事想法、卖点、分章数开关、多选标签均正确回显
- [ ] 打开一个改造前创建的老作品，立项面板正常显示且可保存
- [ ] `parsePremiseFromAi` 单元测试覆盖：标准格式、带 markdown 星号、字段缺失、书名少于 3 个、完全不符格式
- [ ] `normalizeAssets` 单元测试覆盖新字段保留与类型非法时的降级
- [ ] `pnpm -r typecheck` 与 `pnpm -r test` 全绿
